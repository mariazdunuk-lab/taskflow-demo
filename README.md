# TaskFlow — КП 2.4

Стильове оформлення елементів PWA додатків. Продовження проєкту з КП 2.3.

## Як оновити попередній проєкт

1. Якщо сервер запущений, зупиніть його в терміналі клавішами Ctrl+C.
2. Збережіть резервну копію старого проєкту.
3. Розпакуйте архів. Усередині папки `taskflow-demo full` знайдіть `src`, `package.json`, `package-lock.json` та `README.md`.
4. Скопіюйте ці чотири елементи у свою попередню робочу папку проєкту й погодьтеся на заміну. Це папка, де вже є `package.json` і налаштовано Git.
5. Відкрийте цю робочу папку у Visual Studio Code через «Файл → Відкрити папку».
6. Відкрийте «Термінал → Новий термінал».

У попередній робочій папці зберігаються налаштування GitHub і Cloudflare. Створювати новий репозиторій не потрібно. В архіві також є весь код для окремого локального запуску. Залежності `node_modules` і збірка `dist` створюються командами нижче.

## Запуск

Виконайте по черзі:

```bash
npm install
npm run dev
```

Відкрийте адресу з термінала, зазвичай `http://localhost:5173`. Не відкривайте `index.html` подвійним натисканням.

## Що виконано

- Компоненти Framework7 зареєстровано через `registerComponents(app)` перед `app.mount('#app')`.
- Підключено Framework7 Icons.
- Створено три сторінки: головна, завдання, про застосунок.
- Створено спільну нижню панель `AppTabbar.vue` з виділенням активного пункту.
- На головній програмно підраховуються 4 завдання і 2 виконані; показано три останні завдання.
- На сторінці завдань показано назви, описи й статуси чотирьох записів.
- Оформлено картки, списки та адаптивне розташування за допомогою CSS Grid, Flexbox і медіазапиту.
- Збережено PWA-конфігурацію, іконки та генерацію Service Worker.

Дані демонстраційні, як у методичці КП 2.4. Створення, редагування, видалення завдань і LocalStorage у цій роботі не реалізуються. Додаткові завдання не виконувалися.

Нижню панель розміщено у слоті `fixed`, щоб вона залишалася внизу сторінки. `TaskCard.vue` залишився з КП 2.3; нові сторінки використовують розмітку з КП 2.4.

## Основні файли

```text
src/
  components/
    AppTabbar.vue
    TaskCard.vue
  data/tasks.js
  pages/
    HomePage.vue
    TasksPage.vue
    AboutPage.vue
  css/app.css
  main.js
  App.vue
  routes.js
```

`index.html` містить `#app` та підключення `main.js`. `main.js` підключає Vue, Framework7, стилі й іконки. `App.vue` створює `f7-app` та основний `f7-view`. `routes.js` задає переходи `/`, `/tasks/`, `/about/`. Налаштування PWA містяться у `vite.config.js`, публікації — у `wrangler.jsonc`.

## Перевірка і скріншоти

1. Головна: видно статистику «4» і «2», три останні завдання та нижню панель. Зробіть скрін № 1.
2. Натисніть «Завдання»: видно 4 записи з описами й статусами. Зробіть скрін № 2.
3. Натисніть «Про застосунок»: видно опис, технології та версію. Зробіть скрін № 3.
4. Поверніться на головну. Перевірте «Переглянути всі», «Перейти до завдань» та іконку інформації у верхній панелі. Активний пункт нижньої панелі має змінювати колір.
5. Натисніть F12 → Console: перевірте відсутність червоних помилок JavaScript.
6. Натисніть Ctrl+Shift+M, виберіть Responsive і встановіть ширину 320 px. Зробіть скрін № 4 з видимим значенням ширини.
7. Перевірте 375 px, потім 768 px. На 768 px зробіть скрін № 5. Підписи й кнопки не повинні перекриватися.
8. Вимкніть режим мобільного екрана і закрийте DevTools.

## Збірка

Зупиніть сервер через Ctrl+C та виконайте:

```bash
npm run build
```

Після успішного завершення зробіть скрін № 6: результат збірки і повідомлення про генерацію Service Worker. Попередження про розмір JavaScript-файлу понад 500 kB саме по собі не означає помилку збірки.

Потім виконайте:

```bash
npm run preview
```

Відкрийте адресу з термінала, зазвичай `http://localhost:4173`, і ще раз перевірте всі три сторінки та переходи. У `dist` мають бути `manifest.webmanifest`, `sw.js` і файл `workbox-...js`.

## Оновлення GitHub і Cloudflare

У своїй попередній робочій папці, де вже налаштовано Git, відкрийте другий термінал або зупиніть preview через Ctrl+C. Виконайте:

```bash
git status
git add src package.json package-lock.json README.md
git commit -m "Complete KP 2.4: TaskFlow styling and navigation"
git push
```

Якщо Git повідомить `fetch first` або `non-fast-forward`, після створення коміту виконайте:

```bash
git pull --rebase origin main
git push
```

Якщо з'явиться `CONFLICT`, спочатку потрібно розв'язати конфлікт; надішліть текст повідомлення для допомоги.

Якщо GitHub уже підключено до Cloudflare, перевірте нове розгортання після push. Налаштування залишилися від КП 2.3: команда збірки `npm run build`, команда публікації `npx wrangler deploy`, назва Worker — `taskflow-demo`.

Після успішного розгортання зробіть скрін № 7 у Cloudflare і скрін № 8 головної сторінки за публічною адресою. Для звіту також збережіть посилання на власний репозиторій та сайт.

Якщо браузер показує стару версію, перевірте успішність останнього розгортання. Потім на відповідному сайті відкрийте F12 → Application → Service workers → Unregister і перезавантажте сторінку. Переконайтеся, що в DevTools вимкнено Offline.
